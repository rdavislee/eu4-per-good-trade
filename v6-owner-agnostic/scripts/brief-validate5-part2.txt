## What to produce

A verdict on every claim in the inventory, as a markdown file at
`C:\Users\rdavi\OneDrive\Documents\Paradox Interactive\Europa Universalis IV\mod\per-good-trade\v6-owner-agnostic\validation-v6-round5-part2.md`. One row or block per claim ID, carrying:

- **ID** — the same ID the inventory uses. Every ID in the inventory gets a verdict; none are skipped.
- **Verdict** — `CONFIRMED`, `PARTIAL`, `REFUTED`, or `UNTESTABLE`.
  - `CONFIRMED`: you re-derived the claim from a primary source and got the same answer.
  - `PARTIAL`: some of it holds and some does not — say precisely which part fails.
  - `REFUTED`: you re-derived it and got a different answer, or the source says otherwise.
  - `UNTESTABLE`: no available source can settle it. Say what source would.
- **Method** — what you actually did. The command you ran, the file and line you read, the
  computation you performed. "Read the spec" is not a method; the spec is the thing under test.
- **Evidence** — the output. Numbers you got, the text you read, the exit status.

Then a summary: counts by verdict, and the list of REFUTED and PARTIAL IDs.

## How to reach a verdict

Re-derive. Every confirmation must come from a source outside the document. If the spec says a figure
is 12.23 and a script prints 12.23, that is a confirmation of the document against the script — say
so, and say whether you also checked the script does what its name claims. If a figure has no source
you can reach, that is `UNTESTABLE`, not `CONFIRMED`.

Do not confirm on plausibility. A figure that looks about right is not confirmed. A mechanism
description that reads like how EU4 works is not confirmed until you have found it in a file or seen
it in the game. Several figures in earlier versions of this document survived three audits because
each auditor found them plausible.

Do not inherit the inventory's judgments. It records what the document says its provenance is; that
provenance may be wrong, and a claim the inventory calls "computed by a named script" may name a
script that does not compute it. Check.

Where a claim is quantitative and a script exists to compute it, run the script. Where a claim is
quantitative and no script exists, write one. Where you write an instrument that reimplements
something the mod already implements, validate your instrument against the shipped one on a case
whose answer is known before you trust any of its output — a reimplementation missing a step reports
a stable-looking wrong answer as readily as an unstable one.

Report what you found, including where you could not settle something.
